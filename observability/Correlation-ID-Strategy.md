# Correlation ID Strategy

## Overview

Distributed integration systems process a single business operation across multiple services, queues, functions, and APIs. Without a consistent correlation identifier propagated through every hop, reconstructing the full execution path of a failed or slow request is impossible in production. A correlation ID is the thread that ties log entries from APIM, Functions, Service Bus, Logic Apps, and downstream services into a single traceable operation.

This document defines the canonical correlation ID strategy for all integration patterns in this library: how IDs are generated, which headers carry them, how they propagate across service boundaries, and how they are logged.

---

## Standard Headers

Two correlated but distinct identifiers are used:

### X-Correlation-ID
A business-level correlation identifier that scopes a logical business operation — a single API request, a message processing chain, or a saga instance. This is the identifier used in support tickets, business audit logs, and operational alerting.

- **Format:** UUID v4 string (`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`)
- **Header name:** `X-Correlation-ID`
- **Origin:** Generated at the entry point (APIM for API traffic; message publisher for event-driven traffic) if not already present
- **Propagation:** Carried through every hop as a header (HTTP) or message property (Service Bus, Event Hubs)
- **Lifetime:** For the duration of the business operation; a saga may carry the same correlation ID through all its steps

### traceparent (W3C Trace Context)
A distributed tracing identifier compliant with the [W3C Trace Context specification](https://www.w3.org/TR/trace-context/). Used by OpenTelemetry-compatible observability tools (Application Insights, Jaeger, Zipkin) to reconstruct distributed traces.

- **Format:** `00-{trace-id}-{parent-id}-{flags}`
  - `trace-id`: 16-byte hex (32 characters)
  - `parent-id`: 8-byte hex (16 characters)
  - `flags`: 1-byte hex (`01` = sampled, `00` = not sampled)
  - Example: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
- **Header name:** `traceparent`
- **Optional companion header:** `tracestate` (vendor-specific trace state)
- **Origin:** Generated by the first instrumented service in the chain
- **Propagation:** Every instrumented service reads, updates the `parent-id`, and re-emits

The `traceparent` `trace-id` component serves as a technical distributed trace identifier, distinct from the business-level `X-Correlation-ID`. Both are needed — `X-Correlation-ID` for business correlation and support, `traceparent` for technical trace reconstruction.

## Propagation Rules

### Rule 1: Generate at Entry, Never Overwrite Existing

```
IF X-Correlation-ID is absent on inbound request → generate a UUID v4 and set it
IF X-Correlation-ID is present on inbound request → use the provided value unchanged
```

Never overwrite a provided correlation ID. Consumer-provided correlation IDs are meaningful to the consumer for their own tracking. Overwriting them breaks the caller's ability to correlate their logs with yours.

### Rule 2: Propagate to All Downstream Calls

Every downstream HTTP call, Service Bus message send, and Event Grid event publish must carry the correlation ID. No exception.

For HTTP: pass as `X-Correlation-ID` request header.
For Service Bus: set as `CorrelationId` property and also in `ApplicationProperties["X-Correlation-ID"]`.
For Event Grid: include in event `data` payload and as a CloudEvent extension attribute.

### Rule 3: Return in Response

The `X-Correlation-ID` must appear in every HTTP response — even error responses. This allows callers to correlate their error logs with your logs.

### Rule 4: Log at Every Service Boundary

Every service that receives and processes a message must log the correlation ID as a structured property — not embedded in a log message string. Log it as `correlationId` (camelCase, for consistency with Application Insights's custom dimensions schema).

### Rule 5: Validate but Accept Imperfect Input

If an inbound `X-Correlation-ID` is present but not a valid UUID, accept it anyway (log a warning, but do not reject the request). Some older consumers send non-UUID correlation values. Rejecting them breaks backward compatibility.

## Implementation by Service

### Azure API Management

```xml
<!-- Global APIM policy: generate and propagate correlation ID -->
<inbound>
    <!-- Generate if absent -->
    <set-header name="X-Correlation-ID" exists-action="skip">
        <value>@(Guid.NewGuid().ToString())</value>
    </set-header>
    <!-- Generate traceparent if absent -->
    <set-header name="traceparent" exists-action="skip">
        <value>@{
            var traceId  = Guid.NewGuid().ToString("N") + Guid.NewGuid().ToString("N").Substring(0, 0);
            // Correct: traceparent = 00-{32 hex trace-id}-{16 hex parent-id}-01
            var tid = Guid.NewGuid().ToString("N");
            var pid = Guid.NewGuid().ToString("N").Substring(0, 16);
            return $"00-{tid}-{pid}-01";
        }</value>
    </set-header>
    <!-- Store for use in logging -->
    <set-variable name="correlationId"
        value="@(context.Request.Headers.GetValueOrDefault("X-Correlation-ID", ""))" />
</inbound>
<outbound>
    <!-- Return correlation ID to consumer in response -->
    <set-header name="X-Correlation-ID" exists-action="override">
        <value>@((string)context.Variables["correlationId"])</value>
    </set-header>
</outbound>
<on-error>
    <set-header name="X-Correlation-ID" exists-action="override">
        <value>@((string)context.Variables["correlationId"])</value>
    </set-header>
</on-error>
```

### Azure Functions (.NET Isolated)

```csharp
// Middleware: extract and store correlation ID from HTTP trigger or Service Bus trigger
public class CorrelationIdMiddleware : IFunctionsWorkerMiddleware
{
    public async Task Invoke(FunctionContext context, FunctionExecutionDelegate next)
    {
        string correlationId;

        // Extract from HTTP trigger
        if (context.BindingContext.BindingData.TryGetValue("Headers", out var headersObj)
            && headersObj is string headersJson)
        {
            var headers = JsonSerializer.Deserialize<Dictionary<string, string>>(headersJson)!;
            correlationId = headers.GetValueOrDefault("X-Correlation-ID")
                            ?? Guid.NewGuid().ToString();
        }
        else
        {
            // Extract from Service Bus trigger ApplicationProperties
            correlationId = context.BindingContext.BindingData
                .GetValueOrDefault("CorrelationId")?.ToString()
                ?? Guid.NewGuid().ToString();
        }

        // Store in context items for use by function code
        context.Items["CorrelationId"] = correlationId;

        // Set on all outbound HTTP requests via HttpClient
        using (LogContext.PushProperty("correlationId", correlationId))
        {
            await next(context);
        }
    }
}
```

```csharp
// HttpClient propagation via DelegatingHandler
public class CorrelationIdHandler : DelegatingHandler
{
    private readonly IHttpContextAccessor _accessor;

    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request, CancellationToken cancellationToken)
    {
        // Propagate correlation ID to downstream HTTP calls
        if (!request.Headers.Contains("X-Correlation-ID"))
        {
            var correlationId = Activity.Current?.GetBaggageItem("correlationId")
                                ?? Guid.NewGuid().ToString();
            request.Headers.Add("X-Correlation-ID", correlationId);
        }

        // Propagate traceparent (OpenTelemetry handles this automatically)
        return await base.SendAsync(request, cancellationToken);
    }
}
```

### Azure Service Bus Message Publishing

```csharp
// Set correlation ID on outbound Service Bus messages
var message = new ServiceBusMessage(payload)
{
    MessageId     = eventId,
    CorrelationId = correlationId,  // Built-in property — filterable
    Subject       = eventType
};

// Also set in ApplicationProperties for SQL filter access and maximum compatibility
message.ApplicationProperties["X-Correlation-ID"] = correlationId;
message.ApplicationProperties["traceparent"]       = Activity.Current?.Id ?? "";
```

### Azure Service Bus Message Receiving

```csharp
// Extract correlation ID from received message
[Function("ProcessOrder")]
public async Task Run(
    [ServiceBusTrigger("orders-queue", Connection = "ServiceBus")]
    ServiceBusReceivedMessage message,
    ServiceBusMessageActions messageActions)
{
    var correlationId = message.CorrelationId
                        ?? message.ApplicationProperties.GetValueOrDefault("X-Correlation-ID")?.ToString()
                        ?? Guid.NewGuid().ToString();

    using var activity = _activitySource.StartActivity("ProcessOrder");
    activity?.SetTag("correlationId", correlationId);
    activity?.SetTag("messageId", message.MessageId);

    _logger.LogInformation("Processing order message {MessageId} for correlation {CorrelationId}",
        message.MessageId, correlationId);

    // ... processing ...
}
```

### Logic Apps

In Logic Apps, propagate `X-Correlation-ID` through workflow variables and HTTP action headers:

```json
"Initialize_CorrelationId": {
  "type": "InitializeVariable",
  "inputs": {
    "variables": [{
      "name": "correlationId",
      "type": "string",
      "value": "@{coalesce(triggerOutputs()?['headers']?['X-Correlation-ID'], guid())}"
    }]
  }
},
"Call_Downstream_Service": {
  "type": "Http",
  "inputs": {
    "method": "POST",
    "uri":    "https://downstream-service.internal/api/process",
    "headers": {
      "X-Correlation-ID": "@variables('correlationId')",
      "Content-Type":     "application/json"
    },
    "body": "@body('Parse_Message')"
  }
}
```

## Structured Logging Format

All services must emit the correlation ID as a structured property named `correlationId` in their log output. For Application Insights, this appears in the `customDimensions` column:

```csharp
// Serilog: add correlationId to all log entries in scope
using (LogContext.PushProperty("correlationId", correlationId))
using (LogContext.PushProperty("messageId", message.MessageId))
{
    _logger.LogInformation("Processing started");
    // ... processing ...
    _logger.LogInformation("Processing completed");
}
```

```kql
// Application Insights: query all log entries for a specific correlation ID
traces
| where customDimensions["correlationId"] == "3fa85f64-5717-4562-b3fc-2c963f66afa6"
| project timestamp, message, severityLevel, operation_Name, cloud_RoleName
| order by timestamp asc
```
